# LSTK 3D Configurator — параметрическое ядро

Шаг 1 из плана: структура DDD, процедурная геометрия профилей ЛСТК и ферм, 3D-вьюпорт.
Next.js 16 (App Router, static export) · React Three Fiber · Zustand · Tailwind v4 · Vitest.

```bash
cd lstk-configurator
npm install
npm run dev        # http://localhost:3100
npm test           # 160 тестов домена и геометрии
npm run typecheck
npm run build      # статический экспорт в out/
```

## Структура

```
src/
  domain/                  чистый TypeScript, миллиметры, без three.js
    geometry/              векторы, скругление гибов, offset полилинии, площадь
    profiles/              C / U / Z / Hat: сечение, свойства, каталог, валидация
    members/               элемент в пространстве, ориентация, операции пробивки
    trusses/               генератор ферм, решатель равновесия, производственная модель
    machines/              профилегибочные линии: данные со ссылкой на источник, проверка изготовимости
  render/                  адаптеры three.js: меши, instancing, материалы (метры)
  features/
    viewport/              R3F Canvas, свет, сетка, камера
    configurator/          панель управления, сборка сцены, раскрой
  store/                   Zustand
  app/                     Next.js App Router
```

Правило зависимостей: `domain` ничего не импортирует из `render`/`features`. BOM, CNC- и
DXF-экспорт будут читать `domain` напрямую, без WebGL.

## Что реализовано

**Профили** (`domain/profiles`). Сечение строится как средняя линия с гибами радиуса
`r + t/2`, затем смещается на ±t/2. Отсюда точная площадь, центр тяжести, Ix/Iy, ширина
штрипса (развёртка) и масса с цинком. Тест сверяет площадь с t × развёртка для всего
каталога. Каталог — типовые размеры, **не ТУ конкретного производителя**.

**Операции** (`domain/members/punching.ts`): сервисные отверстия, димплы/болтовые отверстия
в узлах, шахматные термопрорези. `validateFeatures` ловит выход за элемент, заход на гиб и
пересечение отверстий между собой. Например, термопрорези по умолчанию пересекаются с
сервисными отверстиями, и это ошибка раскладки, а не геометрии.

**Фермы** (`domain/trusses`): треугольные (Финк, Хау, Пратт), трапециевидные (Хау, Пратт),
с параллельными поясами (Пратт, Хау, Уоррен).
- Расчётная модель: узлы и стержни. `checkDeterminacy` решает систему метода узлов: ферма
  должна быть неизменяемой и статически определимой. Тест прогоняет каждую комбинацию
  формы, решётки и числа панелей.
- `solveTruss` даёт усилия в стержнях; сверено с ручным расчётом.
- Производственная модель: прямой пояс катается одним куском, длиннее заготовки — стык в
  узле. Свес продолжает верхний пояс. Пары димплов ставятся в каждом узле.

**3D** (`render/`). `createCProfileMesh`, `createUProfileMesh`, `createZProfileMesh`,
`createHatProfileMesh`, `createTrussMesh`, `createMembersGroup`.
- Быстрый режим: одна геометрия единичной длины на профиль и `InstancedMesh`. Сцена в тысячи
  элементов стоит столько вызовов отрисовки, сколько в ней разных профилей.
- Детальный режим: стенка — пластина с настоящими отверстиями, полки и гибы — отдельные
  полосы. Тест сверяет удалённый объём стали с площадью отверстий.

**Линия** (`domain/machines`). Golden Integrity LGS C89: каждое значение из коммерческого
предложения хранится со ссылкой на страницу, неизвестное — как `null` с пояснением. Каталог C89
строится из этих данных. `memberOnMachine` проверяет профиль, толщину и операции, а также
сверяет развёртку со штрипсом из КП. Сводка данных: [docs/golden-integrity-c89.md](docs/golden-integrity-c89.md).

## Чего здесь нет и почему

- **Длины — по осевым линиям.** Для станка нужна деталировка узлов: зазоры вложения, торцевые
  подрезки, `lip-cut`/`flange-cut`. Она зависит от конкретной линии. Без неё CSV для станка
  выдаст детали, которые не соберутся.
- **Нет подбора сечений.** Решатель проверяет схему, а не сталь: устойчивость, местную и
  искажённую потерю устойчивости, узлы по СП РК EN 1993-1-3 не считает.
- **Нагрузки по регионам РК не заполнены.** Снег, ветер и сейсмику надо брать из
  нормативных карт с указанием источника по каждой строке, а не из памяти.
- **«Инженерный штамп» в PDF.** Программа может выдать предварительный подбор с пометкой
  «требует проверки», но не подпись проектировщика.
- **Формат CNC.** DSTV/NC1 — для линий горячекатаного проката. Профилегибочные линии ЛСТК
  (Howick, FrameCAD, Scottsdale и др.) используют свои форматы. Экспорт делается под
  конкретную линию.
- **Route Handlers и Python-сервис** не работают при статическом экспорте на GitHub Pages и
  потребуют отдельного хостинга.
