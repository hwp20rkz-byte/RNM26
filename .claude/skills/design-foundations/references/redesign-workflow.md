# Competitive Refresh Workflow

A distinct task type: take an existing site (client legacy site or a public brand as portfolio concept work) and ship a version that clearly wins on taste, clarity, and performance. Constraint-driven: six phases, no skipping.

## The six-phase plan
1. **Diagnostic audit** — crawl the current site; document five measurable weaknesses (structure, typography, hierarchy, motion discipline, performance) with screenshots or metrics as evidence
2. **Positioning brief** — one page: what the brand actually is (past marketing copy), current feel (3 adjectives), target feel (3 adjectives), primary conversion action
3. **Structural references** — synthesis per `design-foundations/references/reference-synthesis.md`, aligned to the new brief (structure only, never visual identity)
4. **Design lock** — tokens + section wireframe + motion notes (design-foundations pipeline)
5. **Build + motion** — static-first assembly, then motion pass per motion-design; max 2 memory-layer moves
6. **Polish + proof** — site-polish-qa checklist, preview deploy, **comparison artifact** (before/after per section)

## Brief generation pattern (from a URL)
1. What the brand actually is — 3 sentences, dig past the homepage headline
2. Current site feel — 3 adjectives
3. Target feel — 3 adjectives
4. Five weaknesses with evidence (not opinions)
5. Recommended dominant layout pattern (one of the 7 in `layout.md`)

## The comparison deliverable
Every refresh ships with a side-by-side artifact: section-by-section before/after + one sentence per design decision. For client work this is the review deck; for public concept work it becomes the case-study skeleton.

## Boundaries
- Public concept refreshes: label as unaffiliated; never reproduce logos, photography, or copy — re-think structure with original assets
- Client refreshes: the five audit weaknesses become acceptance criteria; re-test them in final QA
