# ROADMAP — 5 итераций до релиза

Каждый спринт — 2 недели. Оценки условные (нет команды/данных о скорости) —
[Предположение], калибровать после спринта 1.

## Спринт 1 — Фундамент и данные (MVP-скелет)
- Backend: доменные сущности, миграции (Flyway), базовый auth (логин/пароль ADMIN/CHAIRMAN).
- Seed: здания Ақмешіт 9/9-1/9-2/9А/9Б, персонал N/W, справочник работ (пустые эталонные фото).
- Frontend: карта двора (статичный OSM-слой + SVG-полигоны зданий и зон без интерактивного рисования).
- Критерий готовности: ADMIN может залогиниться, увидеть карту с зонами, CRUD зон через API (без UI-конструктора).

## Спринт 2 — Конструктор карты и планировщик
- UI-инструменты рисования зон/точек (полигон, точка, привязка zoneType).
- Планировщик: календарь, bulk-schedule из шаблона, drag-and-drop назначения N/W.
- Канбан-доска (Запланировано → В работе → На проверке → Выполнено), без realtime ещё.
- Критерий готовности: председатель создаёт расписание уборки на неделю за <5 минут.

## Спринт 3 — Мобильный чек-лист и WhatsApp
- WhatsApp OTP/Magic Link авторизация (Green API интеграция, `WhatsAppGateway` абстракция).
- PWA чек-лист: чек-боксы, гео-валидация, фото/видео до/после со штампом.
- `dispatch-whatsapp` — рассылка персональных ссылок на задачи дня.
- Критерий готовности: исполнитель по ссылке из WhatsApp без пароля открывает свои задачи на смену.

## Спринт 4 — Чат, Helpdesk, геймификация
- WebSocket-чат (STOMP), вкладка «Потребности» с шаблонами заявок.
- Геймификация: очки «Чистый двор», бейджи скорости/качества, прогресс-бар смены.
- Кайдзен-сравнение эталон/факт (наложение фото До/После рядом с референсом).
- Критерий готовности: исполнитель видит свой прогресс и баллы в реальном времени.

## Спринт 5 — Аналитика, отчёты, релиз
- Дашборд эффективности (время на операцию, % закрытия, просрочки).
- Генератор PDF/DOCX отчётов с галереей и таблицами затрат времени.
- Хардненинг PWA (offline-очередь синхронизации для чек-листа, service worker),
  нагрузочный прогон auth/чата, security-ревью (OWASP), финальный UX-проход по Claude Design.
- Критерий готовности: председатель формирует месячный отчёт в DOCX/PDF в один клик.

## Явно вне рамок 5 спринтов (не MVP)
- Мультиобъектность (несколько ЖК на один тенант) — текущая модель на один комплекс.
- Биллинг/подписки.
- Полноценная роль «Житель» с обращениями — упомянута как «замечания жильцов» в отчётах,
  но отдельного личного кабинета жителя в требованиях нет — не проектирую его, чтобы не
  придумывать несуществующий scope.
