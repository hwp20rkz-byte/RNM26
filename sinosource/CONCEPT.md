# SinoSource OS: концепция системы для байер-агента в Китае

Версия 0.1 · 27.11.2026 · статус: концепт до пилота

Пометки уверенности: **[Точно]** означает, что есть проверяемый источник, **[Вероятно]** — сильный вывод, **[Предположение]** — гипотеза, которую нужно проверить на пилоте. Все цены и сроки в документе относятся к **[Предположение]**, пока пилот не даст замеров.

---

## 1. Главное в трёх абзацах

Задача не в том, чтобы «ИИ искал на Alibaba». Задача в том, чтобы одна заявка клиента проходила через конечный автомат из девяти состояний, и на каждом шаге была понятна цена, владелец и срок. ИИ-агенты закрывают рутину: разбор заявки, перевод, поиск, первичную переписку, сравнение. Человек принимает три решения: цену оферты, выбор поставщика и отправку обязывающих сообщений.

Архитектура определяется тремя внешними ограничениями. Первое: у крупных B2B-площадок нет открытого API поиска для покупателей. Второе: личный WeChat не автоматизируется без риска блокировки. Третье: языковые модели ошибаются в цифрах. Система, которая игнорирует эти ограничения, работает до первой блокировки аккаунта или первой ошибки в цене.

Готового open-source продукта для этой задачи нет **[Вероятно]**, ни в поиске по GitHub, ни в обзорах он не нашёлся. Есть блоки: единый инбокс (Chatwoot), модель закупок (ERPNext, Odoo), каркасы агентов (LangGraph), SDK для WeChat (Wechaty). Ядро (модель заявки, оркестратор, биллинг в четырёх валютах) нужно писать самим.

## 2. Пользователи и роли

| Роль | Где работает | Что делает в системе |

| Администратор | Кабинет | Прайс-лист, курсы и наценки, шаблоны, права, аудит |

## 3. Процесс: конечный автомат заявки

```
NEW → QUALIFYING → OFFER_SENT → PAID → SEARCHING → RFQ_SENT → NEGOTIATING
    → VERIFYING → PROPOSAL_SENT → SAMPLES → ORDER → CLOSED
                     ↘ LOST (с причиной) из любого состояния
```

| № | Этап | Владелец | Вход | Выход (событие) | Целевой SLA |
|---|---|---|---|---|---|
| 1 | Приём | Intake-агент | Сообщение в любом канале | Карточка заявки создана | 5 мин |
| 2 | Квалификация и ТЗ | Analyst-агент + **менеджер** | Карточка | ТЗ полное, вопросы закрыты | 30 мин |
| 3 | Оферта и предоплата | Pricing-агент + **менеджер** | ТЗ | Оплата получена | 1 ч до отправки |
| 4 | Поиск | Search-агент | Оплаченная заявка | 5–10 кандидатов с оценкой | 2–4 ч |
| 5 | RFQ | Writer-агент | Кандидаты | RFQ отправлены | 15 мин |
| 6 | Переписка | Liaison-агент + оператор | RFQ | Котировки собраны | 1–3 дня |
| 7 | Проверка завода | Verifier-агент + оператор | Котировки | Отчёт о заводах | 1 день |
| 8 | Сравнение и КП | Reporter-агент + **менеджер** | Котировки + проверка | КП отправлено клиенту | 2 ч |
| 9 | Образцы, сделка | Менеджер | Решение клиента | Договор / закрытие | по договору |

Правила автомата:
- Поиск (этап 4) запускается только после оплаты услуги. Исключение даёт менеджер вручную, например для постоянного клиента.
- Каждый переход пишется в журнал аудита: кто, когда, на основании чего.
- Нарушение SLA поднимает задачу в очереди менеджера и отправляет уведомление.

## 4. ИИ-агенты: спецификация

Общие принципы:
- Агент — это промпт, набор инструментов и **строгая схема выхода** (JSON Schema). Свободного чата между агентами нет: оркестратор передаёт агенту срез состояния заявки и получает структурированный результат.
- Любая цифра (цена, MOQ, срок) хранится вместе с `source_ref`, ссылкой на сообщение или страницу, откуда она взята. Цифра без источника в КП не попадает.
- Каждый вызов модели пишется в журнал: модель, токены, стоимость, длительность, вход и выход.
- Модели **[Предположение по распределению]**: Claude Sonnet 5.5 как основная, Haiku 5.5 для извлечения полей и классификации, Opus 5.5 для переговоров, спорной проверки завода и сложных ТЗ.

| Агент | Вход | Выход | Инструменты | Ограничения |
|---|---|---|---|---|
| **Intake** | Текст, фото, голос, файлы | `RequestCard`: товар, кол-во, брендинг, сроки, доставка, бюджет, вложения | STT (Whisper или аналог), OCR, vision, парсер Excel | Не придумывает поля, пустое остаётся пустым |
| **Analyst** | `RequestCard` | Полнота ТЗ, вопросы клиенту, код ТН ВЭД с уверенностью, флаги риска (двойное назначение, сертификация) | Справочник ТН ВЭД, чек-листы по категориям | Код ТН ВЭД с уверенностью ниже 0,8 проверяет менеджер |
| **Pricing** | ТЗ, история клиента | Тариф, цена в базовой валюте, пересчёт в ₽ ₸ ¥ $, срок фиксации курса | Прайс-лист, курсы ЦБ РФ, НБ РК, НБК | Скидки выше порога утверждает менеджер |
| **Search** | ТЗ, фото | Список кандидатов: товар, поставщик, цена-диапазон, MOQ, тип (фабрика/посредник), оценка | 1688 Open Platform, поиск по фото, поставщики данных, база своих заводов | Только законные источники (раздел 6) |
| **Writer** | ТЗ, кандидаты, глоссарий | RFQ и ответы на 中文 и English | Шаблоны, глоссарий отрасли, память переписки | Не обещает объём, сроки оплаты или эксклюзив без менеджера |
| **Liaison** | Входящие сообщения заводов | Перевод, извлечённые поля котировки, черновик ответа | Единый инбокс, парсер котировок | Отправка в личный WeChat и чат Alibaba только руками оператора |
| **Verifier** | Данные поставщика | Отчёт: юрлицо, возраст, уставный капитал, профиль, экспорт, признаки посредника | Публичные реестры КНР, лицензия 营业执照, данные площадок, видео-аудит | Вывод «фабрика» требует минимум двух независимых признаков |
| **Reporter** | Котировки, отчёты | Таблица сравнения, рекомендация, КП в PDF на языке клиента | Шаблоны КП, генератор PDF, графики | Контакты завода скрыты до оплаты следующего этапа |

Схема оценки поставщика (Search + Verifier), стартовые веса **[Предположение]**:

```
score = 0.30·тип(фабрика=1, посредник=0.3)
      + 0.20·соответствие ТЗ
      + 0.20·цена (нормированная к медиане выборки)
      + 0.10·возраст компании (cap 10 лет)
      + 0.10·экспортный опыт / сертификаты
      + 0.10·скорость и качество ответа
```

Веса калибруются по истории: какие поставщики дошли до сделки.

## 5. Архитектура

```
┌───────────────────── Кабинет оператора и клиента (Next.js 16) ─────────────────────┐
│ Очередь заявок · карточка · утверждения · инбокс · КП · аналитика · админка        │
└─────────────────────────────────────────────────────────────────────────────────────┘
        │                       │                          │
┌───────┴──────┐      ┌─────────┴─────────┐       ┌────────┴────────┐
│ Каналы       │ ───▶ │ Ядро              │ ───▶  │ Агенты          │ ───▶ Источники
│ Telegram     │      │ Единый инбокс     │       │ Intake, Analyst │      1688 Open Platform
│ WhatsApp     │      │  (Chatwoot)       │       │ Pricing, Search │      Поставщики данных
│ WeCom        │      │ Оркестратор       │       │ Writer, Liaison │      Помощник в браузере
│ Почта        │      │ Очередь задач     │       │ Verifier,       │      RFQ на площадках
│ Веб-форма    │      │ Правила и SLA     │       │ Reporter        │      Курсы ЦБ РФ, НБ РК, НБК
└──────────────┘      │ Биллинг и курсы   │       │ (Claude API)    │
                      └───────────────────┘       └─────────────────┘
┌──────────────────────────────────── Данные ─────────────────────────────────────────┐
│ Postgres (+ pgvector для поиска похожих товаров) · S3 для файлов · журнал аудита    │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

Решения:
- **Оркестратор** — свой конечный автомат поверх очереди задач (Inngest или pg-boss). Каждый шаг агента — идемпотентная задача с повторами. LangGraph подходит как альтернатива, если команда пишет на Python **[Вероятно]**.
- **Единый инбокс** — Chatwoot (MIT) **[Точно: лицензия и каналы Telegram, WhatsApp, почта по README]**. WeCom подключается своим API-каналом через вебхуки Chatwoot.
- **Помощник в браузере** — расширение Chrome: кнопка «сохранить в заявку» на карточке товара или поставщика (Alibaba, MIC, 1688) и перенос сообщений из чата Alibaba. Действие выполняет человек, расширение только структурирует страницу, которую оператор уже открыл.
- **Журнал аудита** — append-only таблица: каждый вызов модели и инструмента, каждое утверждение человека. Отсюда считается себестоимость заявки и обучаются промпты.

### Модель данных (основные таблицы)

| Таблица | Ключевые поля |
|---|---|
| `clients` | страна, валюта по умолчанию, каналы, реквизиты |
| `requests` | client_id, state, owner_id, sla_due_at, tariff_id, source_channel |
| `request_specs` | request_id, версия, поля ТЗ (JSONB), hs_code, hs_confidence |
| `offers` | request_id, tariff_id, base_usd, fx_snapshot_id, total_in_client_currency, valid_until, approved_by |
| `payments` | offer_id, amount, currency, provider, paid_at |
| `fx_snapshots` | date, source (CBR, NBK, PBoC), USD/RUB, USD/KZT, USD/CNY, markup_pct |
| `suppliers` | название (中文/EN), город, тип, лицензия, рейтинг, история |
| `listings` | supplier_id, platform, url, title, price_min/max, currency, moq, captured_by |
| `rfqs` | request_id, supplier_id, language, channel, body, sent_by, sent_at |
| `threads` / `messages` | канал, направление, текст, перевод, chatwoot_id |
| `quotes` | request_id, supplier_id, unit_price, currency, moq, lead_time, sample_cost, certs, **source_message_id** |
| `verifications` | supplier_id, признаки, вывод, проверил |
| `proposals` | request_id, quotes[], recommendation, pdf_url, sent_at |
| `agent_runs` | request_id, agent, model, tokens_in/out, cost_usd, duration_ms, input, output |
| `time_entries` | request_id, user_id, stage, minutes |

## 6. Доступ к площадкам: что законно и что работает

| Уровень | Источник | Что даёт | Уверенность |
|---|---|---|---|
| 1. Официальный API | 1688 Open Platform: поиск по ключевым словам, поиск по фото (拍立淘, `item_search_img`), карточки. Подпись AppKey/AppSecret, квоты | Цены, MOQ, продавцы, фото | **[Вероятно]**: описано в статьях разработчиков на Alibaba Cloud, условия допуска уточнять на open.1688.com |
| 2. Данные по договору | Поставщики данных и акторы Apify по Alibaba, Made-in-China, 1688 | Выдача в JSON | **[Точно]**: такие сервисы существуют. **Риск**: многие из них парсят площадки, поэтому условия использования нужно проверять юридически |
| 3. Помощник в браузере | Расширение в сессии оператора | Любая открытая карточка | **[Вероятно]**: минимальный риск, так как действует человек |
| 4. RFQ на площадке | Alibaba RFQ, Made-in-China Sourcing Request | Входящие котировки | **[Точно]**: MIC обещает до 20 котировок по одобренному запросу |

Чего **не** делаем: массовый парсинг поисковой выдачи с серверов, рассылку сообщений с личных аккаунтов, обход капчи.

Для Alibaba.com: открытого API поиска для покупателей нет, Open Platform доступна одобренным партнёрам **[Вероятно, по сторонним источникам]**. Собственный ИИ-агент Alibaba, Accio Work, в июле 2026 получил Sourcing Toolkit, который ведёт покупателя от поиска до оплаты внутри экосистемы Alibaba **[Точно, по пресс-релизам]**. Это конкурент на этапе поиска, но не на работе агента с клиентом.

## 7. Мессенджеры

| Канал | Режим | Как | Примечание |
|---|---|---|---|
| Telegram | Автомат | Bot API | Основной канал с клиентами РФ и РК |
| Почта | Автомат | IMAP/SMTP | Главный канал с экспортными отделами заводов |
| WhatsApp | Полуавтомат | WhatsApp Business Cloud API | Свободный ответ в окне 24 ч, дальше шаблоны **[Точно]** |
| WeCom (企业微信) | Полуавтомат | Официальный API WeCom | Можно добавлять контакты из обычного WeChat **[Вероятно]**, основной канал с заводами |
| Личный WeChat | Только черновик | Оператор копирует и отправляет | Wechaty технически позволяет больше, но это риск блокировки |
| Чат Alibaba | Только черновик | Через кабинет, расширение переносит сообщения | |

«Полуавтомат» означает, что агент готовит ответ, а оператор отправляет его одной кнопкой. Без утверждения уходят только служебные сообщения: «заявка получена», «оплата получена», «КП готово».

## 8. Деньги: прайс-лист и валюты

### 8.1. Прайс-лист услуг (стартовая гипотеза)

Демо-курс: 1 $ = 82 ₽ = 520 ₸ = 7,15 ¥ **[Предположение: курс для примера; в системе берётся ежедневно]**.

| Услуга | Что входит | $ | ₽ | ₸ | ¥ |
|---|---|---:|---:|---:|---:|
| Экспресс-подбор | 3 проверенных поставщика, цены, MOQ, 48 ч | 150 | 12 300 | 78 000 | 1 073 |
| Полный сорсинг | 5–10 заводов, RFQ, торг, сравнение, КП | 450 | 36 900 | 234 000 | 3 218 |
| Проверка завода (онлайн) | Видео-аудит, документы, отчёт | 250 | 20 500 | 130 000 | 1 788 |
| Образцы и переговоры | Заказ образцов, торг, контроль сроков | 200 | 16 400 | 104 000 | 1 430 |
| Сопровождение заказа | Контроль качества, логистика, оплата заводу | 3–5% от суммы заказа | | | |
| Выездной аудит | Визит на завод | 350 + дорога | 28 700 | 182 000 | 2 503 |

### 8.2. Формула пересчёта

```
price_client = round_to_step( base_usd × fx(USD→currency, date) × (1 + markup_conv) , step(currency) )
markup_conv = 2%        # покрывает разницу курсов и комиссии
step: ₽ = 100, ₸ = 1000, ¥ = 1, $ = 1
fx: RUB — ЦБ РФ, KZT — Нацбанк РК, CNY — Народный банк Китая (кросс-курс через USD)
Курс фиксируется в оферте на 3 дня (fx_snapshot_id).
```

Таблица в 8.1 показана без 2% надбавки, чтобы цифры совпадали с презентацией.

### 8.3. Себестоимость заявки «Полный сорсинг» [Предположение]

| Статья | Оценка | Как считается в системе |
|---|---:|---|
| ИИ (8 агентов, токены) | ≈ 4 $ | сумма `agent_runs.cost_usd` |
| Данные и API площадок | ≈ 3 $ | счётчик вызовов × тариф |
| Время оператора | ≈ 12 $ (90 мин) | `time_entries`, таймер в кабинете |
| Мессенджеры, хостинг | ≈ 1 $ | распределение месячных затрат |
| **Итого** | **≈ 20 $** | при цене 450 $ |

Главная экономия идёт не от ИИ, а от времени человека: ожидаем, что менеджер будет вести в 3–4 раза больше заявок в неделю **[Предположение]**.

| Фронт и бэкенд | Next.js 16 (как в этом репозитории), TypeScript, zod | Один язык, готовые компоненты |
| БД | Postgres + pgvector (Supabase или свой) | Заявки, поиск похожих товаров по эмбеддингам |
| Очередь задач | Inngest или pg-boss | Идемпотентные шаги, повторы, расписание SLA |
| ИИ | Claude API с tool use, строгие JSON-схемы | Сильный китайский и русский, длинный контекст |
| Инбокс | Chatwoot (self-hosted) | MIT, каналы из коробки |
| Файлы | S3-совместимое хранилище | Фото, PDF, вложения |
| Браузер | Расширение Chrome (Manifest V3) | Уровень доступа 3 |
| Голос | Whisper или аналог | Голосовые заявки |
| Хостинг ПД | РФ (152-ФЗ) и/или РК | Требование локализации персональных данных |

## 11. План

| Релиз | Срок | Состав | Критерий успеха |
|---|---|---|---|
| MVP | 6 недель | Telegram + почта, Intake, Pricing, Writer, помощник в браузере, КП в PDF, 4 валюты, журнал и таймер | 20 оплаченных заявок, время до оферты ≤ 1 ч |
| Версия 1 | +8 недель | 1688 API и поиск по фото, Liaison (WeCom, WhatsApp, почта), парсинг котировок, Verifier, кабинет клиента | Время до первой подборки ≤ 2 ч, ×2 заявок на менеджера |
| Версия 2 | +12 недель | База заводов с рейтингом, повторные заявки, счета и акты в ₽ и ₸, роли и SLA, аналитика маржи | ×3–4 заявок на менеджера, 30% заявок закрываются из своей базы |

MVP намеренно обходится без автоматического поиска. Он проверяет главную гипотезу: готовы ли клиенты платить за поиск заранее.

## 12. Метрики

- Конверсия: заявка → оплата оферты → КП → образцы → заказ.
- Время: до оферты, до первой подборки, до КП.
- Себестоимость заявки по статьям, маржа по тарифу.
- Качество ИИ: доля полей, исправленных человеком; доля котировок с ошибкой извлечения.
- Поставщики: скорость ответа, доля «фабрика» среди отобранных, доля дошедших до сделки.

## 13. Риски

| Риск | Ответ |
|---|---|
| Блокировка аккаунта площадки или мессенджера | Только API и действия человека, лимиты, без массовых рассылок |
| ИИ ошибся в цене или MOQ | `source_ref` обязателен, проверка менеджером перед отправкой |
| Посредник вместо фабрики | Verifier, два независимых признака, видео-аудит |
| Клиент забрал подборку и ушёл к заводу | Предоплата, контакты скрыты до оплаты следующего этапа |
| Скачок курса | Фиксация на 3 дня, надбавка 2% |
| Санкционные и экспортные ограничения | Analyst отмечает двойное назначение и маршрут, финальное решение за менеджером |
| Персональные данные | Локализация в РФ/РК, шифрование, роли |
| Изменение условий API площадок | Адаптер на каждый источник, деградация до уровня 3 |

## 14. Решения до старта

1. Приоритетные клиенты: РФ или РК. От этого зависят платёжный контур, валюта счёта и место хранения данных.
2. Есть ли доступ к 1688 Open Platform. Без него автоматический поиск появится только в версии 1 через данные по договору.
3. Кто оператор в Китае: свой сотрудник с WeCom компании или внешний агент.
4. Пилот: 20 реальных заявок за 4 недели на прототипе кабинета, с ручной работой там, где ещё нет автоматики.
