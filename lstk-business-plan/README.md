# LSTK Business Plan — конструктор бизнес-плана строительства домов из ЛСТК

Интерактивная модель: вводите типы домов, себестоимость, план продаж, условия оплаты,
капзатраты и финансирование — получаете помесячный P&L, денежный поток, NPV, IRR,
окупаемость, точку безубыточности, пиковую потребность в деньгах и чувствительность.

Адрес после деплоя: `https://hwp20rkz-byte.github.io/RNM26/lstk-business-plan/`

## Что умеет

- **Типы домов** — площадь, цена за м², срок стройки, доля в продажах.
- **Каркас** — своя линия профилирования (цена рулона, мощность линии) или покупной каркас;
  оборудование линии автоматически выпадает из капзатрат при покупном каркасе.
- **Себестоимость** — статьи на м² или на дом, материалы/работы, привязка к типам домов.
- **План продаж** — выход на план, сезонность по месяцам.
- **Оплата** — аванс / промежуточный / остаток при сдаче; доля материалов, закупаемых сразу.
- **Финансирование** — капитал, кредит с льготным периодом и аннуитетом.
- **Налоги** — упрощённая декларация (% от поступлений) или КПН с переносом убытков.
- **Результаты** — показатели, предупреждения (кассовый разрыв, убыточный дом, нехватка
  мощности линии), остаток денег, EBITDA, экономика дома, «торнадо» чувствительности NPV,
  годовая и помесячная таблицы.
- **Файлы** — автосохранение в браузере, экспорт/импорт плана (JSON), таблица CSV для Excel,
  печать/PDF.

Значения по умолчанию — ориентиры, не рыночные данные. Их нужно заменить своими сметами.

## Ограничения модели

- Число договоров в месяц — ожидаемое среднее (может быть дробным).
- Выручка и себестоимость признаются равномерно по ходу стройки.
- NPV/IRR — по потоку проекта без кредита и без остаточной стоимости после горизонта.
- Суммы без НДС; лимиты упрощённого режима не проверяются.

## Разработка

```bash
cd lstk-business-plan
npm install
npm run dev     # http://localhost:5174
npm test        # тесты расчётной модели (src/model/calc.test.ts)
npm run build
```

Расчёт — чистые функции в `src/model/calc.ts`, интерфейс — `src/ui/`. Токены дизайна — `src/tokens.css`.

## Деплой

Сайт GitHub Pages у репозитория один: корень занимает QazaqOSI, рядом лежат `/hoa-yard-service/`
и это приложение. Общий `.github/workflows/deploy-pages.yml` собирает его с
`GITHUB_PAGES_BASE=/RNM26/lstk-business-plan/` и кладёт в `out/lstk-business-plan/`.
Workflow запускается только с ветки по умолчанию, поэтому в прод приложение попадёт после
слияния ветки `claude/lstk-business-plan-constructor-xv799j`.

`vite.config.ts` задаёт пустой inline-конфиг PostCSS, чтобы не подхватывать Tailwind
QazaqOSI из `postcss.config.mjs` в корне репозитория.

Настоящий поддомен (`lstk.<домен>`) на этом Pages-сайте невозможен: у репозитория один
сайт и один custom domain. Для поддомена нужен свой домен и отдельный хостинг
(отдельный репозиторий с Pages либо Cloudflare Pages / Vercel / Netlify).
